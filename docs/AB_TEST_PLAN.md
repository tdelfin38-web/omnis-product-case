# A/B test plan: статус проверки рецепта

## Гипотеза

Если после загрузки рецепта показать пользователю понятный статус, ориентировочное время проверки и следующий шаг, то вырастет конверсия из отправленного рецепта в начатое оформление заказа — без роста обращений в поддержку и отмен.

## Дизайн

| Параметр | План |
| --- | --- |
| Популяция | Совершеннолетние пользователи, успешно отправившие рецепт в разрешённом пилотном контуре |
| Control | Текущий нейтральный экран «Рецепт принят» |
| Treatment | Статус, ожидаемое время проверки, уведомление о результате и следующий шаг |
| Рандомизация | На уровне пользователя, 50/50 |
| Primary metric | `checkout_started / prescription_submitted` |
| Guardrails | Время проверки, отмены, обращения в поддержку, ошибки/инциденты |

## Критерий решения

Запускать вариант дальше, если primary metric растёт статистически и practically significantly при отсутствии ухудшения guardrails. Размер эффекта и длительность рассчитываются до старта на базовой конверсии и минимально значимом эффекте; не «останавливать» тест по случайному раннему результату.

## Интерпретация

- Положительный результат: раскатить постепенно и проверить эффект по сегментам.
- Нулевой: изучить воронку, тексты и время фактической проверки.
- Негативный или рост обращений: остановить treatment и провести качественные интервью.

Тест не меняет порядок юридической проверки рецепта и не тестирует медицинские решения.
